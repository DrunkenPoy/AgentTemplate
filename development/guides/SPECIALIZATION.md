# Software development: additional interview and verification

Determine whether this is a new project or an existing codebase. For existing code, read repository instructions, build configuration, and tests before asking about facts available there.

Discuss:

- Product, users, main features, and any specified language/framework/runtime.
- Code location, dependency installation, and actual build/run/test commands.
- Deployment targets and external services; whether deployment is in scope.
- Repository host, base branch, and how operational records are shared.

Record verified commands and success conditions in PROJECT.md using the selected project language. Plan reproduction for bugs and appropriate checks for new behavior. Do not weaken expectations or coverage merely to pass tests. Match existing style and change only the requested scope.

When UI changes, define how it will be inspected. Distinguish successful builds, unit tests, and user scenarios. Record unperformed checks and reasons. Do not import game-engine-specific restrictions into this general template.
