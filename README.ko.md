# START.md

[English](README.md) | [한국어](README.ko.md)

AI의 인터뷰에 답하면서 프로젝트의 작업 방식을 설정하는 Windows용 템플릿입니다. 설정 파일을 직접 편집하거나 전체 워크플로우를 미리 익힐 필요가 없습니다.

AI에서 이 폴더를 열고 **“START.md를 읽고 초기 설정을 진행해 주세요.”**라고 요청하세요. AI가 먼저 사용할 언어를 묻고, 템플릿 선택·AI 역할 배정·필요한 도구 점검을 안내합니다.

| 폴더 | 용도 | 시작 환경 |
|---|---|---|
| [development](development/START.md) | 범용 소프트웨어 개발 | Claude Code 또는 Codex CLI |
| [game-development](game-development/START.md) | 특정 엔진에 종속되지 않는 게임 개발 | Claude Code 또는 Codex CLI |
| [general-work](general-work/START.md) | 기획·보고서·조사 및 업무용 파일 제작 | CLI 또는 Codex/Claude 데스크톱 |

## 시작 전: 필요한 사용 환경

| 항목 | 준비할 내용 |
|---|---|
| 운영체제 | Windows PC. 템플릿과 보조 스크립트는 Windows를 대상으로 하며, macOS/Linux 지원은 포함하지 않습니다. |
| 시작할 AI 도구 | 개발용은 Claude Code 또는 Codex CLI를 사용합니다. 일반업무는 Codex 또는 Claude 데스크톱에서도 시작할 수 있습니다. CLI는 터미널에서 실행하는 AI 도구를 뜻합니다. |
| 폴더 접근 | AI가 로컬 템플릿 폴더 전체를 읽고 프로젝트 기록을 저장할 수 있어야 합니다. 채팅에 START.md 내용만 붙여 넣는 것으로는 폴더 접근 권한이 생기지 않습니다. |
| PowerShell | 보조 스크립트 실행에는 `pwsh` 명령으로 사용하는 **PowerShell 7 이상**이 필요합니다. `powershell.exe`로 실행하는 Windows PowerShell 5.1은 사용할 수 없습니다. |
| 계정과 모델 | 선택한 클라우드 AI 서비스에 로그인하고 사용할 모델에 접근할 수 있어야 합니다. 계정·구독·모델 사용 권한은 템플릿에 포함되지 않습니다. |
| 네트워크 | 클라우드 AI 호출·로그인·필요한 파일 다운로드에는 인터넷 연결이 필요합니다. Ollama를 사용하면 설정한 Ollama 서비스에 연결할 수 있어야 합니다. |

**모든 AI 도구를 설치할 필요는 없습니다.** 우선 사용할 AI 하나로 시작하세요. 설정 과정에서 선택한 역할에 필요한 도구를 확인하고, 부족한 항목을 안내합니다.

| 선택한 경우에만 필요한 항목 | 추가 준비 사항 |
|---|---|
| Codex 자동 호출 | Codex CLI를 설치하고 로그인합니다. Windows 실행 환경에서 해당 명령에 접근할 수 있어야 합니다. |
| Claude 자동 호출 | Claude Code를 설치하고 로그인합니다. 제공되는 네이티브 서브에이전트 도구 또는 템플릿의 CLI 어댑터로 Claude 담당자를 호출합니다. |
| Gemini 자동 호출 | 호환되는 Antigravity `agy` CLI와 로그인, 선택 모델의 사용 권한이 필요합니다. 다른 Gemini CLI를 대상으로 만든 어댑터는 아닙니다. |
| Ollama | Ollama 서비스가 실행 중이어야 하며, 사용할 모델을 미리 다운로드해야 합니다. |
| 개발 또는 Git 기반 기록 관리 | Git과 저장소 접근 권한이 필요합니다. 개발용은 PR 생성 수단도 필요하며, GitHub에서는 로그인된 GitHub CLI 등을 사용할 수 있습니다. |
| 소프트웨어·게임 빌드 | 프로젝트에 필요한 컴파일러·SDK·엔진·의존성·테스트 도구를 설정 과정에서 확인합니다. 게임 엔진은 포함되어 있지 않습니다. |
| 업무용 결과물 | 선택한 Word·PowerPoint·Excel·PDF 파일을 만들고 확인할 도구가 필요합니다. 사용 가능한 도구를 설정 과정에서 확인하며, 특정 오피스 제품을 필수로 요구하지는 않습니다. |

자세한 설치·연결 방법은 선택한 템플릿의 도구 안내를 참고하세요: [범용개발](development/guides/TOOLS.md), [게임개발](game-development/guides/TOOLS.md), [일반업무](general-work/guides/TOOLS.md). PowerShell이 없다면 [Microsoft 설치 안내](https://learn.microsoft.com/powershell/scripting/install/installing-powershell-on-windows)를 따르세요.

## 다섯 단계로 시작하기

### 1. PC에 파일 준비하기

이 저장소의 GitHub 페이지에서 ZIP을 다운로드해 압축을 풀거나, Git으로 복제하세요. 아래 자리표시자는 현재 저장소의 실제 URL로 바꿔주세요.

~~~powershell
git clone "YOUR_REPOSITORY_URL"
~~~

이 README와 루트 START.md가 들어 있는 폴더를 사용합니다. 이미 PC에 파일이 있다면 다운로드를 건너뛰고 해당 폴더를 사용하세요.

### 2. AI 도구에서 폴더 열기

다음 중 사용할 방식 하나를 선택하세요.

| 시작 도구 | 해야 할 일 |
|---|---|
| Codex 또는 Claude Code CLI | 저장소 폴더에서 터미널을 열고 `codex` 또는 `claude`를 실행합니다. |
| Codex 데스크톱 — 일반업무 | 저장소 폴더를 로컬 프로젝트로 열고, 그 파일에 접근할 수 있는 채팅을 시작합니다. |
| Claude 데스크톱 — 일반업무 | 로컬 파일 작업이 가능한 모드에서 저장소 폴더를 연결하고, 폴더에 접근할 수 있는 채팅을 시작합니다. |

예를 들어 저장소를 `C:\Work\AgentTemplate`에 두었다면 다음과 같이 실행합니다.

~~~powershell
Set-Location "C:\Work\AgentTemplate"
codex
~~~

경로는 실제 폴더 위치로 바꾸세요. Claude Code를 사용하려면 `codex` 대신 `claude`를 실행합니다. 이 명령은 선택한 CLI가 이미 설치되어 있다는 전제입니다.

앱에서 로컬 파일을 읽을 수 있어도 Windows 명령은 실행하지 못할 수 있습니다. 이 경우 인터뷰와 인수인계 기록을 진행한 뒤, 외부 AI 호출 자동화는 실행 가능한 CLI 환경에서 이어갑니다. 자세한 내용은 [앱 안내](general-work/guides/APPS.md)를 참고하세요.

### 3. AI에게 시작 문장 보내기

아래 문장을 **AI와 대화하는 입력창**에 붙여 넣으세요. 터미널 셸에 명령어처럼 직접 입력하는 문장이 아닙니다.

> START.md를 읽고 초기 설정을 진행해 주세요. 필요한 질문은 주제별로 나누어 해주세요. 기존 설정이 있으면 먼저 읽고, 초기화하지 말고 이어서 진행해 주세요.

보조 스크립트를 사용자가 직접 실행할 필요는 없습니다. AI가 START.md를 따라 진행하고, 사용할 수 있는 도구가 있으면 스크립트를 실행합니다.

### 4. 설정 질문에 답하기

첫 질문은 대화와 프로젝트 문서에 사용할 언어입니다. 담당 AI가 지원하는 언어를 선택할 수 있습니다. 템플릿 자체는 영어로 유지되지만, 이후 질문·보고서·결과물에는 선택한 언어를 사용합니다.

이어서 다음 내용을 확인합니다.

- 범용개발·게임개발·일반업무 중 어떤 템플릿을 사용할지
- 한 프로젝트용으로 복사할지, 한 작업 공간에서 여러 프로젝트를 관리할지
- 프로젝트 이름·목표·완료 조건
- 총괄·실무·검수를 각각 어떤 AI가 담당할지
- 업무에 필요한 스킬·MCP, 기존 연결 상태, 추가 연결에 필요한 계정 접근 범위
- 어느 시점에 사용자 확인을 받을지, 검수를 몇 차례 진행할지

AI는 답변을 받는 대로 저장합니다. 로그인이나 폴더 연결처럼 사용자가 직접 해야 하는 단계가 안내되면 완료해 주세요. 필요한 사용자 조작 없이 AI가 대신 로그인할 수 있는 것은 아닙니다.

사용할 템플릿을 이미 정했다면 해당 폴더만 복사해 그 안에서 시작해도 됩니다. LICENSE와 숨김 파일을 함께 보존하세요. 각 템플릿은 다른 두 폴더 없이도 사용할 수 있습니다.

### 5. 준비 상태를 확인하고 첫 작업 요청하기

AI가 템플릿의 연결 안내에 따라 필요한 스킬·MCP를 찾고, 합의된 범위에서 지원되는 설치·설정을 수행합니다. 사용자가 직접 해야 하는 로그인·접근 동의·재시작은 안내하고, 이어서 진행할 단계를 기록합니다. 사용자가 도구 이름을 미리 알고 있을 필요는 없습니다.

담당 AI의 연결과 필수 스킬·MCP를 실제로 사용할 AI·환경에서 각각 확인합니다. 필수 항목이 미완료이면 준비 완료와 테스트 외 작업 호출을 막고, 선택 항목의 제한사항은 기록합니다. 스크립트는 기록된 확인 결과를 검사하며, 실제 연결 검사는 설정을 진행하는 AI가 수행합니다. 현재 환경이 지원하지 않는 설치·연결까지 자동으로 수행할 수 있는 것은 아닙니다.

설정이 끝나면 구체적인 작업을 요청하세요. 예를 들면 다음과 같습니다.

> 경쟁사 조사 보고서를 Word 문서로 만들어 주세요. 먼저 조사 범위를 확인하고 작업 계획을 제안해 주세요.

AI가 계획을 제시하고 사용자와 작업 규모를 결정한 뒤, 저장된 검수·승인 규칙에 따라 진행합니다. 개발 작업은 PR 생성까지 진행하며, 최종 병합은 사용자가 합니다.

## 사용하지 않는 템플릿 정리하기

템플릿을 복사하지 않고 이 폴더에서 바로 사용했다면, 설정이 끝난 뒤 AI가 나머지 두 템플릿 폴더를 정리할지 묻습니다. 정리하면 이후 세션에서 선택한 템플릿만 참조합니다. 언제든 직접 요청할 수도 있습니다.

| 선택 | 결과 |
|---|---|
| 아카이브(권장) | 사용하지 않는 템플릿 폴더와 `tests/`를 `_archive/`에 zip으로 보관하고 작업 폴더에서 제거합니다. AI는 이를 참조하지 않습니다. |
| 삭제 | 폴더를 지웁니다. 프로젝트 기록이 들어 있는 폴더는 삭제를 거부합니다. |
| 유지 | 아무것도 바꾸지 않습니다. |

~~~powershell
pwsh -NoProfile -File ./scripts/Set-ActiveTemplate.ps1 -Keep general-work
# 보관한 폴더를 나중에 되살리기:
pwsh -NoProfile -File ./scripts/Set-ActiveTemplate.ps1 -Restore development
~~~

`-WhatIf`를 붙이면 미리보기만 합니다. 정리된 폴더로 가는 이 README의 링크는 복원 전까지 열리지 않습니다. `_archive/`는 Git에서 제외됩니다.

## 설정과 결과물은 어디에 저장되나요?

선택한 템플릿 폴더 안에서 다음 위치를 사용합니다.

| 위치 | 내용 |
|---|---|
| `workspace/` | 프로젝트 하나를 관리하는 방식의 기록 폴더 |
| `projects/<project-id>/` | 여러 프로젝트를 관리할 때 각 프로젝트의 개별 기록 폴더 |
| `project.json` | 언어·담당 AI·공유 가능한 스킬 및 MCP 요구사항 |
| `project.local.json` | PC 경로·연결 정보·확인 결과. Git에서 제외하며 인증정보는 해당 도구의 인증 저장소에 보관 |
| `PROJECT.md`, `DECISIONS.md`, `BACKLOG.md` | 목표, 사용자 결정, 진행 상황 |
| `handoffs/`, `reviews/` | 담당 AI가 수행·확인한 내용과 다음 담당자에게 전달할 기록 |
| `work/`, `outputs/` | 기본 작업 폴더와 최종 결과물. 기존 프로젝트 폴더를 대신 사용할 수도 있음 |

표의 마지막 다섯 행에 있는 파일과 하위 폴더는 해당 프로젝트의 기록 폴더 안에 있습니다. 저장소 루트에 바로 생성되는 것은 아닙니다.

## 나중에 이어서 작업하거나 AI 바꾸기

같은 폴더를 열고 다음과 같이 요청하세요.

> START.md를 읽고, 저장된 언어·설정·최근 인수인계를 확인한 뒤 프로젝트를 이어서 진행해 주세요.

프로젝트가 여러 개라면 대상 프로젝트 이름도 알려주세요. AI가 기록된 답변을 재사용하므로 인터뷰를 처음부터 반복하지 않습니다. 언어 필드가 없는 이전 프로젝트는 언어만 한 번 확인하고, 나머지 설정과 기록은 보존합니다.

재사용 프롬프트·안내·빈 양식은 영어로 유지합니다. 작성되는 문서의 제목과 본문은 선택한 언어를 사용합니다. 원문 인용·코드 식별자·파일 경로·설정 키·기계가 읽는 상태 토큰은 그대로 유지합니다.

## 포함된 기능

- 초기 인터뷰, 중단된 설정 재개, AI 세션 간 인수인계
- 공통 프로젝트 설정과 PC별 경로 설정의 분리
- 작업·결정·인수인계·검수 양식
- Codex CLI, Claude Code 역할별 에이전트, Antigravity agy, Ollama 호출 어댑터
- 호출 기록, 실패 상태, 시간 제한, 같은 작업의 중복 호출 방지
- 개발용 커밋·push·PR 생성 절차. 병합은 사용자 담당
- Word·PowerPoint·Excel·PDF 제작 및 검증 안내

총괄 AI는 WORKFLOW.md에 따라 인터뷰·단계 진행·결과 판정을 수행합니다. 보조 스크립트는 기록 초기화·설정 검사·담당 AI 호출을 처리합니다. START.md가 앱에 없는 파일·명령 실행 권한을 새로 부여하지는 않습니다. 앱에서 Windows CLI를 실행할 수 없으면 기록을 보존해 CLI 환경으로 인계합니다.

개발용 AGENTS.md와 CLAUDE.md는 원본 AgentWS 파일과 바이트 단위로 동일하게 보존되어 있습니다. 추가 규칙은 별도 문서에서 관리합니다.

## 검증

실제 AI 호출·로그인·모델 접근·앱 연결은 사용자 환경의 초기 설정에서 확인해야 합니다. 모의 검증 통과가 실제 서비스 연결을 보장하지는 않습니다.

최근 자동 검증은 **Windows·PowerShell 7.6.5**에서 수행했으며, 스킬·MCP 준비 상태와 역할별 확인 결과 검사를 포함한 **모의 검사 123개를 통과**했습니다. 실제 모델 호출·스킬 설치·MCP 서비스 연결·데스크톱 앱 연결은 검증하지 않았습니다.

~~~powershell
pwsh -NoProfile -File ./tests/Verify-Templates.ps1
# 첫 번째 명령이 출력한 fixture 경로를 사용합니다.
pwsh -NoProfile -File ./tests/Verify-Edges.ps1 -Fixture "출력된 fixture 경로"
pwsh -NoProfile -File ./tests/Verify-Integrations.ps1 -Fixture "출력된 fixture 경로"
~~~
