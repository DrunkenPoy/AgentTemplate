# START.md

**START.md는 AI에게 총괄·실무·검수 역할을 나누고, 프로젝트 설정부터 작업·검수·인수인계까지 관리하도록 돕는 워크플로우 템플릿입니다.**

[English](README.md) | [한국어](README.ko.md)

Windows·macOS에서 소프트웨어 개발, 게임 개발, 일반업무에 사용할 수 있습니다. 클라우드 AI와 Ollama 기반 로컬 LLM을 지원하며, AI의 질문에 답하면 프로젝트 설정을 저장합니다.

## 빠른 시작

1. 이 저장소를 ZIP으로 다운로드해 압축을 풀거나 Git으로 복제합니다.
2. 루트 `START.md`가 있는 폴더에서 Codex CLI 또는 Claude Code를 실행합니다. 일반업무는 로컬 폴더에 접근할 수 있는 Codex/Claude 데스크톱에서도 시작할 수 있습니다.
3. AI 대화창에 **“START.md 진행해 줘”**라고 입력합니다.
4. 사용할 언어, 프로젝트 목표, 담당 AI, 검수·승인 방식에 관한 질문에 답합니다. 기존 설정이 있으면 재사용합니다.
5. 도구 연결과 준비 상태 확인이 끝나면 첫 작업을 요청합니다.

Windows에서 저장소가 `C:\Work\AgentTemplate`에 있다면:

~~~powershell
Set-Location "C:\Work\AgentTemplate"
codex
~~~

macOS에서 저장소가 `~/Work/AgentTemplate`에 있다면:

~~~bash
cd ~/Work/AgentTemplate
codex
~~~

경로는 실제 위치로 바꾸세요. 선택한 CLI가 설치되어 있어야 하며, Claude Code는 `codex` 대신 `claude`로 실행합니다. 로컬 모델 실행 방법은 아래 [로컬 LLM 안내](#로컬-llm으로-사용하기)를 참고하세요.

시작 문장은 터미널 셸이 아닌 **AI 대화창**에 입력합니다. 보조 스크립트는 AI가 사용할 수 있는 도구로 실행합니다. 앱에서 로컬 명령 실행을 지원하지 않으면 인터뷰와 인수인계를 저장하고 CLI에서 이어갑니다. 자세한 내용은 [앱 안내](general-work/guides/APPS.md)를 참고하세요.

### 설정 질문

새 설정의 첫 질문은 대화와 프로젝트 문서에 사용할 언어입니다. 기존 설정은 저장된 언어를 재사용합니다. 담당 AI가 지원하는 언어를 선택할 수 있습니다. 템플릿 자체는 영어로 유지되지만, 이후 질문·보고서·결과물에는 선택한 언어를 사용합니다.

이어서 다음 내용을 확인하며, 저장된 설정이 있으면 재사용합니다.

- 범용개발·게임개발·일반업무 중 어떤 템플릿을 사용할지
- 한 프로젝트용으로 복사할지, 한 작업 공간에서 여러 프로젝트를 관리할지
- 프로젝트 이름·목표·완료 조건
- 총괄·실무·검수를 각각 어떤 AI가 담당할지
- 업무에 필요한 스킬·MCP, 기존 연결 상태, 추가 연결에 필요한 계정 접근 범위
- 어느 시점에 사용자 확인을 받을지, 검수를 몇 차례 진행할지

AI는 답변을 받는 대로 저장합니다. 로그인이나 폴더 연결처럼 사용자가 직접 해야 하는 단계가 안내되면 완료해 주세요. 필요한 사용자 조작 없이 AI가 대신 로그인할 수 있는 것은 아닙니다.

사용할 템플릿을 이미 정했다면 해당 폴더만 복사해 그 안에서 시작해도 됩니다. LICENSE와 숨김 파일을 함께 보존하세요. 각 템플릿은 다른 두 폴더 없이도 사용할 수 있습니다.

### 연결 확인과 첫 작업

AI가 템플릿의 연결 안내에 따라 필요한 스킬·MCP를 찾고, 합의된 범위에서 지원되는 설치·설정을 수행합니다. 사용자가 직접 해야 하는 로그인·접근 동의·재시작은 안내하고, 이어서 진행할 단계를 기록합니다. 사용자가 도구 이름을 미리 알고 있을 필요는 없습니다.

담당 AI의 연결과 필수 스킬·MCP를 실제로 사용할 AI·환경에서 각각 확인합니다. 필수 항목이 미완료이면 준비 완료와 테스트 외 작업 호출을 막고, 선택 항목의 제한사항은 기록합니다. 스크립트는 기록된 확인 결과를 검사하며, 실제 연결 검사는 설정을 진행하는 AI가 수행합니다. 현재 환경이 지원하지 않는 설치·연결까지 자동으로 수행할 수 있는 것은 아닙니다.

설정이 끝나면 구체적인 작업을 요청하세요. 예를 들면 다음과 같습니다.

> 경쟁사 조사 보고서를 Word 문서로 만들어 주세요. 먼저 조사 범위를 확인하고 작업 계획을 제안해 주세요.

AI가 계획을 제시하고 사용자와 작업 규모를 결정한 뒤, 저장된 검수·승인 규칙에 따라 진행합니다. 개발 작업은 PR 생성까지 진행하며, 최종 병합은 사용자가 합니다.

</details>

## 로컬 LLM으로 사용하기

**Ollama 기반 로컬 LLM으로도 사용할 수 있습니다.** macOS에서 Codex CLI와 `gemma4-31b-64k:latest`를 연결해 동작을 확인한 사용자 테스트 사례가 있습니다.

Ollama 서비스를 실행하고 사용할 모델을 준비한 뒤, 템플릿 폴더에서 실행하세요. 아래 모델 이름은 테스트에 사용한 로컬 태그이며, 자신의 Ollama에 설치된 이름에 맞추면 됩니다.

~~~bash
codex --oss -m gemma4-31b-64k:latest -p local-ollama
~~~

`-p local-ollama`는 미리 설정한 Codex 프로필을 선택합니다. 해당 프로필이 없다면 Ollama를 명시해 시작할 수 있습니다.

~~~bash
codex --oss --local-provider ollama -m gemma4-31b-64k:latest
~~~

실행 후 AI 대화창에 **“START.md 진행해 줘”**라고 요청하면 됩니다. 옵션 설명은 [공식 Codex CLI 문서](https://learn.chatgpt.com/docs/developer-commands?surface=cli)를 참고하세요.

Codex CLI를 통해 로컬 모델을 사용하는 방식과 템플릿의 Ollama 직접 호출 어댑터는 구분됩니다. 직접 호출 어댑터는 전달받은 텍스트로 응답을 생성하며 파일 수정이나 명령 실행 도구는 제공하지 않습니다. 작업·검수 역할의 모델과 연결은 초기 설정에서 각각 확인합니다.

## 프로젝트 연결

### 새 프로젝트

아이디어만 있어도 시작할 수 있습니다. 빈 프로젝트 폴더나 Git 저장소를 미리 만들 필요는 없습니다.

> START.md 진행해 줘. 기존 프로젝트는 없고, 개인 할 일 관리 앱을 새로 만들고 싶어.

AI가 맞는 템플릿과 사용 위치를 확인하고 설정을 저장합니다. 실제 앱이나 게임 엔진 프로젝트 파일은 초기 설정 후 첫 개발 작업에서 생성합니다.

다른 프로젝트의 설정이 이미 있다면 **“기존 프로젝트를 재개하지 말고 새 프로젝트를 설정해 줘”**라고 알려주세요. 기존 기록을 보존하면서 별도로 시작합니다.

### 기존 프로젝트

설정 과정에서 기존 프로젝트 폴더의 위치를 알려주고 작업 경로를 확인하세요. 이후 세션도 선택한 템플릿의 START.md에서 시작해 워크플로우 지침과 저장된 기록을 읽도록 합니다.

## 이어서 작업하기

같은 폴더를 열고 다음과 같이 요청하세요.

> START.md를 읽고, 저장된 언어·설정·최근 인수인계를 확인한 뒤 프로젝트를 이어서 진행해 주세요.

프로젝트가 여러 개라면 대상 프로젝트 이름도 알려주세요. AI가 기록된 답변을 재사용하므로 인터뷰를 처음부터 반복하지 않습니다. 언어 필드가 없는 이전 프로젝트는 언어만 한 번 확인하고, 나머지 설정과 기록은 보존합니다.

재사용 프롬프트·안내·빈 양식은 영어로 유지합니다. 작성되는 문서의 제목과 본문은 선택한 언어를 사용합니다. 원문 인용·코드 식별자·파일 경로·설정 키·기계가 읽는 상태 토큰은 그대로 유지합니다.

## 기록과 폴더 관리

선택한 템플릿 폴더 안에서 다음 위치를 사용합니다.

| 위치 | 내용 |
|---|---|
| `workspace/` | 프로젝트 하나를 관리하는 방식의 기록 폴더 |
| `projects/<project-id>/` | 여러 프로젝트를 관리할 때 각 프로젝트의 개별 기록 폴더 |
| `project.json` | 언어·담당 AI·공유 가능한 스킬 및 MCP 요구사항 |
| `project.local.json` | PC 경로·연결 정보·확인 결과. Git에서 제외하며 인증정보는 해당 도구의 인증 저장소에 보관 |
| `PROJECT.md`, `DECISIONS.md`, `BACKLOG.md` | 목표, 사용자 결정, 진행 상황 |
| `handoffs/`, `reviews/` | 담당 AI가 수행·확인한 내용과 다음 담당자에게 전달할 기록 |
| `work/`, `outputs/` | 기본 작업 폴더와 최종 결과물. 기존 프로젝트 폴더도 사용 가능 |

표의 마지막 다섯 행에 있는 파일과 하위 폴더는 해당 프로젝트의 기록 폴더 안에 있습니다. 저장소 루트에 바로 생성되는 것은 아닙니다.

<details>
<summary>사용하지 않는 템플릿 정리하기</summary>

템플릿을 복사하지 않고 이 폴더에서 바로 사용했다면, 설정이 끝난 뒤 AI가 나머지 두 템플릿 폴더를 정리할지 묻습니다. 정리하면 이후 세션에서 선택한 템플릿만 참조합니다. 언제든 직접 요청할 수도 있습니다.

| 선택 | 결과 |
|---|---|
| 아카이브(권장) | 사용하지 않는 템플릿 폴더와 `tests/`를 `_archive/`에 zip으로 보관하고 작업 폴더에서 제거합니다. AI는 이를 참조하지 않습니다. |
| 삭제 | 폴더를 지웁니다. 프로젝트 기록이 들어 있는 폴더는 삭제를 거부합니다. |
| 유지 | 아무것도 바꾸지 않습니다. |

~~~powershell
pwsh -NoProfile -File ./scripts/Set-ActiveTemplate.ps1 -Keep general-work
# 보관한 폴더를 나중에 되살리기:
pwsh -NoProfile -File ./scripts/Set-ActiveTemplate.ps1 -Restore development
~~~

`-WhatIf`를 붙이면 미리보기만 합니다. 정리된 폴더로 가는 이 README의 링크는 복원 전까지 열리지 않습니다. `_archive/`는 Git에서 제외됩니다.

## 검증

실제 AI 호출·로그인·모델 접근·앱 연결은 사용자 환경의 초기 설정에서 확인해야 합니다. 모의 검증 통과가 실제 서비스 연결을 보장하지는 않습니다.

최근 자동 검증은 **Windows·PowerShell 7.6.5**에서 수행했으며, 스킬·MCP 준비 상태와 역할별 확인 결과 검사를 포함한 **모의 검사 123개를 통과**했습니다. 실제 모델 호출·스킬 설치·MCP 서비스 연결·데스크톱 앱 연결은 검증하지 않았습니다. 별도로 macOS에서 Codex CLI와 Ollama 로컬 모델을 연결한 사용자 실행 테스트 사례가 있습니다. 위 로컬 LLM 안내에 해당 명령을 기록했으며, macOS에서 전체 자동 검증을 통과했다는 의미는 아닙니다.

<details>
<summary>자동 검증 명령</summary>

~~~powershell
pwsh -NoProfile -File ./tests/Verify-Templates.ps1
# 첫 번째 명령이 출력한 fixture 경로를 사용합니다.
pwsh -NoProfile -File ./tests/Verify-Edges.ps1 -Fixture "출력된 fixture 경로"
pwsh -NoProfile -File ./tests/Verify-Integrations.ps1 -Fixture "출력된 fixture 경로"
~~~
